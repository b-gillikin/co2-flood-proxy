## Native tasks and executable work

[Spatial adapters](../src/applied_spatial_models.py), [data/metrics](../src/applied_water.py), and [named runner](../scripts/185_run_applied_water.py) implement three separate water tasks and same-input compact U-Net/linear-band comparators. They read original rasters directly; no large patch-cache collection is created.

- **TerraMind Tiny:** strict required encoder-key load; author paired S2L1C/S1GRD means/stds, selected layers2/5/8/11, trainable pyramid/UNet decoder, frozen encoder. Real 512px CPU forward/backward passed. Initial batch1 engineering observation: ~0.72s, ~1.3GB peak process RSS; not a comparative speed claim.
- **Galileo Nano:** strict load; single-time VV/VH with native `OURS_S1`, `norm_no_clip`, multiplier2 normalization, actual zero-based acquisition month, 64px subpatches, spatial tokens and linear 8×8-pixel readout. Dry subpatches retained. Real CPU forward/backward passed (~0.022s at batch1, ~0.36GB process RSS). No catchment averaging. Author positive-only preprocessing is not relabeled as the applied population.
- **Prithvi Tiny TL:** strict filtered encoder load, single real frame, six equivalent bands B2/B3/B4/B8A/B11/B12, real time/location, original-grid evaluation after 224px input adaptation, trainable Tiny/UperNet. The older template's `decoder_scale_modules` is no longer accepted by held TerraTorch; an explicit pyramid neck supplies its role. Real CPU forward/backward passed at batch2 (~9.0s, ~5.6GB process RSS). BatchNorm's 1×1 pooling requires training batch≥2; shuffled training drops a final short batch, but **evaluation never drops a chip**. This is a named Tiny adaptation, not exact reproduction of the larger author template.
- **Copernicus-FM:** source radar dataset and mask audit complete; exact native MMSegmentation change head remains **not runnable in the tested Mac overlay**. `mmcv-lite2.1.0/mmsegmentation1.2.2/mmengine0.10.7` pass dependency checks but importing heads requires absent compiled `mmcv._ext`. No dummy extension, silent substitute decoder, classification-only result or claimed successful native spatial run. Resolve a supported compiled runtime or explicitly validate a portable head before fitting this task. Other tasks can proceed.

Visible runtime versions are recorded under [environments/applied](../environments/applied/README.md). New overlays read unchanged held packages through a `.pth`; they are not independent copies. Copernicus-only installs did not modify active runtimes. An initial overlay NumPy/OpenCV/contourpy incompatibility was resolved and `pip check` passes in all three overlays. That check does not substitute for a native import/forward check.

The runner separates `profile` from `train`, preserves labels/unknowns, original-grid evaluation and per-event confusion counts, records checkpoint/input/code/partition hashes, and retains best/last heads and compressed predictions. It refuses to reuse completion markers with changed sources or overwrite incomplete runs. Full fitting still needs the final **validation-only learning-rate comparison for each comparator** and measured device/batch budgets; a default LR shared from the named native task is not evidence that a scratch comparator was fairly tuned. Source-derived epochs/loss/schedulers are visible, float32/MPS and Tiny adaptations are explicit. Published-split reproduction, local-reference rasterization and comparative uncertainty/atlas consolidation are not yet executed.

Galileo's native workflow precomputes frozen spatial features for repeated probe fits. [The feature extractor](../scripts/190_extract_applied_galileo.py) now does that for **all446 chips**, retaining 64 subpatch token grids per chip in float32, with real dates and no label input. Completed in **79.4s** on one CPU thread, **935,386,880 B (0.87GiB)**, ~0.70GB peak process RSS. These are engineering observations under contention, not a hardware-controlled speed comparison. Direct and cached readouts were checked with identical probe weights and preprocessing, including source-NaN mean imputation; unknown labels remain excluded. The queue profiles the cached native head and retains extraction cost separately. It does not charge 50 repeated frozen encoder passes per head epoch or compare head-only time with an entire raw-input pipeline.

The finite [profile queue](../scripts/187_queue_applied_profiles.py) waits for the present MPS owner, then runs one representative training epoch for each of these three compatible native tasks and their two comparators, **one MPS subprocess at a time**. It records failures and full-epoch time/memory before extrapolating the full fitting grid. It does **not** automatically launch hundreds of comparison fits. Initial CPU engineering checks used earlier source snapshots; their manifests remain intact and do not masquerade as the queued, final-source device profiles.
